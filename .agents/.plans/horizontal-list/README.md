## Dependency notes

- 001 precedes 002, 003, and 009 because reliable cache invalidation is a prerequisite
  for item replacement, estimate changes, and axis changes.
- 002 precedes 010 because horizontal mode must not inherit the current index-cache
  corruption on reorder, replacement, prepend, or shrink.
- 009 is deliberately behavior-preserving: it creates the shared geometry vocabulary
  before 010 introduces a second axis.
- 010 provides static LTR horizontal rendering and measurement. 011 owns responsive
  runtime switching, horizontal keyboard semantics, exhaustive E2E coverage, and docs.
- 004–008 are independent and may run in parallel worktrees.

## Product decisions encoded in this batch

- Public orientation is `orientation?: 'vertical' | 'horizontal'`, default `vertical`.
- Add axis-neutral `defaultEstimatedItemSize`; retain
  `defaultEstimatedItemHeight` as a backward-compatible vertical alias.
- Add `align: 'start' | 'end'`; retain `top`/`bottom` as vertical compatibility aliases.
- First release is left-to-right horizontal scrolling. RTL normalization is deferred.
- Orientation may change at runtime. The visible anchor index must survive the switch,
  while measurements from the old axis must not.
- `PRD.md` is deleted in plan 006, per maintainer direction; it is not refreshed.

## Findings considered and rejected

- The old deep-scroll O(index) finding is rejected: PR #423 added block-prefix lookup
  and all current production call sites on `origin/main` pass block sums.
- No reachable high-confidence security issue was found in the library surface.
- Grid/masonry remains outside this component; prior maintainer direction keeps it a
  separate-package concern.
- RTL horizontal scrolling is deferred because browser `scrollLeft` conventions need a
  dedicated compatibility design and cross-browser test matrix.
- Bidirectional prepend loading is deferred until item identity in plan 002 has shipped
  and gathered usage evidence.
