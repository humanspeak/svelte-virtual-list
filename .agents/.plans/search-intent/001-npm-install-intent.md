## Why this matters

The supplied Search Console cluster has roughly 180 impressions and no clicks for
queries such as `npm svelte-virtual package`, `svelte-virtual npm`,
`"svelte-virtual" npm`, and `svelte virtual`. These are transactional searches:
the visitor wants package identity, compatibility, and an install command quickly.
The current `/docs` page includes installation only after an introduction and a
feature list, and its title is broad onboarding copy. Add an indexable `/install`
page whose title, description, H1, opening copy, and first CTA all resolve that
intent without turning it into a thin doorway page.

## Target search presentation

- Title: `Svelte Virtual List npm Package — Install for Svelte 5`
- Meta description: `Install @humanspeak/svelte-virtual-list for Svelte 5. Copy the npm command, see requirements, and render your first virtual list in minutes.`
- H1: `Install Svelte Virtual List`
- Canonical: `https://virtuallist.svelte.page/install`

Keep the title near 50–60 characters and description near 140–160 characters. If
copy must change to meet an enforced limit, preserve the exact package name,
“npm,” “Svelte 5,” and the install action.

## Steps

### Step 1: Add failing search-surface tests

Extend `docs/e2e/demo.test.ts` with one test named with `install intent`. It must
request or visit `/install` and assert the exact title and meta description above,
canonical `/install`, one visible H1, and visible text
`npm install @humanspeak/svelte-virtual-list`. Also assert `/docs` contains a
crawlable link to `/install`.

**Verify**: `pnpm --filter docs test:e2e -- --grep "install intent"` → FAILS because
`/install` does not exist and `/docs` has no `/install` link. If it passes, STOP.

### Step 2: Build the focused `/install` route

Create `docs/src/routes/install/+page.svelte` using the existing docs-site visual
language and `getSeoContext()` metadata pattern. Above the first major scroll break,
render the H1, one-sentence package positioning, the npm command in selectable code,
a keyboard-accessible copy button with visible success feedback, and a primary path
to the minimal usage example. Below it, include only decision-supporting content:
Svelte 5 requirement, zero runtime dependencies, npm/pnpm/yarn commands, a minimal
Svelte snippet, and links to `/docs`, `/examples`, npm, and GitHub. Avoid repeating
the full API reference or stuffing query variants.

Use `@humanspeak/svelte-virtual-list` verbatim in visible copy. The npm command must
be the first command shown; package-manager alternatives come afterward.

**Verify**: rerun the focused E2E command → metadata, H1, canonical, and command
assertions pass; only the `/docs` link assertion may still fail.

### Step 3: Connect onboarding and navigation

Add a natural `/install` link near the top of `docs/src/routes/docs/+page.svx` rather
than removing its useful install section. Add `Install` as a discoverable nav item
in the Get Started section of `docs/src/lib/docsNav.ts`; keep `/docs` as
Introduction and preserve existing breadcrumb/pager behavior. Do not add `/install`
to the docs-only pager unless the existing filter naturally includes it.

**Verify**: focused E2E → all assertions pass.

### Step 4: Build and confirm discovery

Run the docs build. Confirm `/install` appears in the generated sitemap manifest and
the built HTML contains the exact title, description, canonical, H1, and install
command. Add a sitemap assertion to the E2E test if the existing test server exposes
`/sitemap.xml` reliably.

**Verify**: `pnpm --filter docs build` → exit 0; `rg '"/install"' docs/src/lib/sitemap-manifest.json` → one match.

### Step 5: Run the full gate

Run `trunk fmt`, `pnpm --filter docs check`, the full docs E2E suite, and
`trunk check`. Review `git status --short`; only scoped source/test files and
expected generated artifacts may be modified.

**Verify**: all commands exit 0.

## Test plan

The red-first E2E test proves the route, SSR metadata, canonical, visible install
command, and internal discovery. This is the correct layer because search crawlers
consume built HTML. Clipboard behavior should also be asserted if Playwright can
grant clipboard permission reliably; otherwise assert accessible button state and
the post-click success label.

## STOP conditions

- The installed docs-kit cannot render route-specific SEO synchronously.
- A clean docs build does not discover `/install` in the sitemap manifest.
- The requested design requires modifying docs-kit or package runtime source.
- A pre-existing route or redirect already owns `/install` after drift checking.
